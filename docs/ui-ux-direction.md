# 후속 UI·UX 개선 방향

2026-10-04 · 사용자 지정 참고 자료와 실행 순서. 구현은 Opus, 범위·결과 검토는 총괄이 맡는다.

**참고:** [ayghri/i-have-adhd](https://github.com/ayghri/i-have-adhd), [원문 규칙](https://github.com/ayghri/i-have-adhd/blob/main/skills/i-have-adhd/SKILL.md). 확인한 레포는 코딩 에이전트의 답변을 읽고 행동하기 쉽게 만드는 스킬이다. 아래 제품 UI 기준은 그 원칙을 Plannet에 적용한 설계 해석이다. 설치 명령이나 세션 설정 변경은 이 요청의 범위가 아니다.

## 화면 설계 기준

| 참고 원칙 | Plannet 적용 방향 | 확인할 사용자 행동 |
|---|---|---|
| 다음 행동을 먼저 제시 | 화면마다 핵심 행동을 먼저 보이게 하고 부가 도구는 필요할 때 펼침 | 오늘 플랜을 찾아 바로 첫 할 일 입력 |
| 일을 작은 단계로 구분 | 생성·가져오기·복원을 짧은 단계와 명확한 버튼 문구로 구성 | 현재 단계와 다음 행동을 구분 |
| 한 번에 보이는 정보량 축소 | 보조 설정·설명은 접어 두고 중요한 선택부터 제시. 전체 기록은 검색·더 보기로 접근 | 선택지가 늘어도 기록을 빠뜨리지 않고 찾음 |
| 상태와 성과를 보이게 표현 | 현재 플랜·날짜·저장 상태·완료한 일의 구분을 일관되게 표시 | 다시 돌아왔을 때 작업 위치와 저장 여부를 이해 |
| 오류 원인과 다음 행동을 명확히 | 저장 실패·충돌 안내에 초안 보존 여부와 재시도/복구 동작 표시 | 실패 뒤 내용을 잃지 않고 작업 재개 |

기존 `slate`/`indigo` 중심 스타일, 계정 이메일 표시, 키보드 초점·IME·모달 규칙, DB 중심 자동 저장 정책을 유지한다. 실제 측정이나 근거가 없는 완료 예상 시간은 표시하지 않는다. 참고 레포의 출력 규칙을 데이터 개수 제한으로 사용하지 않는다.

## 실행 순서

| 순서 | 묶음 | 현황·완료 기준 |
|---|---|---|
| 1 | 작업 복귀 검토 보완 + W6 | Opus 진행 중. 사용법 초점·자정 이후 오늘 처리, 월요일 기준 주차, 기존 W1~W5 보존·W6 저장 검증 |
| 2 | 안전한 최신화 | **작업자 구현·검증, 총괄 검토 대기, 미배포** ([보고](session-reports/safe-refresh.md)). 탭 재진입·온라인 복구 때 조건부 조회, 미저장·전송 중·충돌·편집 중이면 미루고 상태 안내 |
| 3 | 본격 UI·UX 개선 | 첫 묶음(편집 헤더 한 줄 정리·`⋮` 메뉴·초기화/덮어쓰기 확인 창) **작업자 구현·검증, 총괄 검토 대기, 미배포** ([보고](session-reports/ui-focus.md)). 홈·보조 패널·저장 안내는 후속 |
| 병행/후속 | 성능·접근성 | 초기 로딩·입력 비교 비용은 표본 측정에 따라 개선. 미적용 모달의 공통 동작과 모바일 조작도 함께 검토 |
| 이후 | 데이터 편의·확장 | 계정 전체 내보내기, 삭제 실행 취소, Monthly→Daily 선택적 가져오기, CI·품질 측정 |

홈서버 이전·공개 TLS·실제 OAuth/AI 검증은 서버 준비 시 별도 진행한다. 모든 후순위 기능의 완료를 UI·UX 개선 착수 조건으로 삼지 않는다. 상세 현황과 검증 근거는 [로드맵](roadmap-status.md)과 [UI·UX 검토](ui-ux-review.md)를 따른다.
