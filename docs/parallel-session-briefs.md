## 세션 A — deploy-hardening

**문제:** 배포 세션이 발견한 앱 수준의 미해결 사항을 보완한다. 루트 Docker 빌드의 `COPY . .`에 `k8s/local/`의 로컬 Secret이 포함될 수 있고, API 이미지의 기본 실행 사용자는 root다. Web의 기본 보안 헤더는 현재 Gateway에 의존한다.

**수정 소유 범위**

- `.dockerignore`, 필요 시 새 `apps/api/.dockerignore`
- `apps/api/Dockerfile`, `apps/web/next.config.ts`
- `scripts/deploy-hardening/**`의 새 검증 도구
- `docs/session-reports/deploy-hardening.md`

**완료 기준**

1. 루트에서 직접 Web 이미지를 빌드해도 로컬 Secret·환경 파일·백업·작업 보고/검증 산출물이 빌드 컨텍스트에 섞이지 않는다. 필요한 소스·정상 예제·빌드 입력은 유지한다. 실제 비밀값을 출력하지 말고 가짜 표식 파일로 컨텍스트 제외와 이미지 잔존 여부를 검증한다.
2. API 이미지는 별도 Kubernetes 설정 없이도 기본적으로 non-root로 정상 기동한다. 기존 `apps/api` 빌드 컨텍스트·사전 생성 jar 경로·포트·환경변수 계약은 유지한다. 이번 범위에서는 multi-stage 전환이나 베이스 이미지 업그레이드를 섞지 않는다.
3. Next.js의 `X-Powered-By`를 제거하고 호환되는 기본 보안 헤더를 설정한다. OAuth redirect·정적 파일·PNG 내보내기를 깨뜨리지 않는다. HTTPS 여부를 고려해야 하는 정책은 기존 Gateway 책임과 중복·충돌하지 않게 둔다. `NEXT_DIST_DIR`, `NEXT_TSCONFIG_PATH`, standalone·백업 제외 설정을 보존한다.
4. 독립 이미지/포트에서 Web 응답·API 실행 UID·health·이미지 빌드를 확인한다. `infra/deploy/**`와 API 인증 코드는 읽기 전용으로 두고, 배포 절차에 영향이 있으면 담당자와 총괄 세션에 알린다.

**먼저 읽을 자료:** `docs/deployment-readiness.md`의 발견한 문제, 두 Dockerfile, `.dockerignore`, `apps/web/next.config.ts`, `infra/deploy/scripts/build-images.sh`.

4. 6개 이상 플랜, 동일 제목·서로 다른 템플릿, 검색 결과 없음, 오래된 플랜 선택, 계정 전환을 검증한다. 데스크톱·모바일·키보드로 전체 목록 접근과 선택을 확인한다. 순수 스타일 변경을 위한 별도 테스트는 추가하지 않는다.
