# PostgreSQL 계정 저장 — 통합 인수 보고

2026-09-26 · 사용자 결정: 첫 공개에 계정별 서버 저장 포함, 현재 컴퓨터에서 개발·검증하고 이후 홈서버로 이전. 커밋·push·공개 배포는 하지 않았다. 기존 작업 트리의 변경을 보존했다.

## 완료한 연결

- [저장 계약](../contracts/planner-storage-v1.md)에 맞춰 내부 사용자, 계정 소유권, 플랜별 JSONB·버전·삭제 표식, 원자적 커밋과 영속 저장 영수증을 구현했다.
- Web은 초기 서버 조회가 끝난 뒤 편집을 허용하고 계정별 캐시·초안·진행 중인 저장 요청을 보존한다. 계정 변경·응답 유실·충돌·큰 이전 일부 실패를 구분한다.
- 이전 계정/비로그인 자료는 별도 버튼으로 가져오며 원본 ID·출처 참조·로컬 키를 보존한다. 같은 내용은 건너뛰고 다른 내용은 자동 병합하지 않는다.
- 로컬 PostgreSQL 18.6은 `127.0.0.1:15432`의 전용 Docker 볼륨에서 실행 중이다. 비밀번호는 `infra/storage/.local/default/`의 비공개 파일에 있으며 출력·커밋하지 않았다.
- API 실행은 `npm run api:dev:storage`, DB 상태/백업/중지는 `npm run db:status`, `db:backup`, `db:stop`. Google 설정과 같은 origin 라우팅은 기존 인증 실행 절차를 따른다. 개발용 API/Web을 임의의 기존 포트에 새로 상주시켜 두지는 않았다.
- production 배포는 storage=true와 DB 세 값의 필수 Secret을 참조한다. 기존 local-verify HTTPS 환경은 인증 검증 전용 storage=false로 명시했다. 실제 배포 적용은 하지 않았다.

## 실제 통합 절차

루트에서 `npm run test:storage`를 실행한다. 포트 3690–3695가 비어 있어야 하며 Docker와 Java 21이 필요하다. 이 테스트는 실제 Spring OAuth/session/CSRF와 실제 PostgreSQL을 사용한다. 외부 로그인 제공자만 테스트 OIDC로 바꾸고 실제 Google·외부 AI·개발자 DB는 호출하지 않는다. PostgreSQL의 앱 역할에는 클러스터 관리자 권한이 없다.

1. **두 기기·두 계정:** UI에서 Daily 제목/할 일을 작성 → DB 저장 확인 → 다른 브라우저의 같은 계정에서 복원 → 다른 계정에서는 조회되지 않음. 이전 계정 헤더의 GET/POST는 409이며 다른 계정에 쓰지 않는다.
2. **충돌:** 두 브라우저가 같은 버전을 읽음 → 첫 브라우저 저장 → 두 번째 오래된 수정은 충돌. 서버의 먼저 저장한 내용을 유지하고 두 번째 초안을 파일로 내려받으며 재로드 후에도 보존한다.
3. **응답 유실:** 서버가 commit을 성공시킨 뒤 브라우저 응답만 끊음 → 재로드 → 같은 요청을 재전송 → 레코드 한 개와 동일 버전만 존재.
4. **이전:** Mandalart·Monthly·Block6·Daily·반복·휴일을 익명 키에 준비 → 자동 귀속되지 않음 확인 → 명시적 가져오기 → 전체 JSON·출처 ID 대조 → 원본 키 유지 → 반복 실행해도 버전 증가 없음.
5. **API 재시작:** 저장 뒤 Spring 종료/재시작 → 기존 세션 401 → 재로그인 → 동일 내부 사용자·레코드·UI 내용 복원.
6. **새 DB 복원:** 플랜과 삭제 표식을 저장 → API 쓰기 정지 → 앱 역할로 custom-format dump → 새 DB 생성·앱 역할로 단일 트랜잭션 복원 → 사용자/레코드/영수증/Flyway 전체 행 체크섬 대조 → 복원 DB에 API 재연결 → 재로그인·조회·이전 requestId 재전송의 동일 응답 확인.

첫 통합 실행의 두 실패는 테스트가 모달 뒤의 기존 플랜 버튼을 선택한 것과 저장 상태 문구 불일치였다. 테스트 선택자를 보정한 뒤 전체를 새 DB로 재실행했다. 검토 중 캐시 재로드의 편집 대기, 빈 설정의 불필요한 저장, undefined 필드 비교를 보완했고 최종 소스로 검증했다. 검증 종료 시 자체 생성한 컨테이너·볼륨·덤프만 정리한다.

## 남은 범위

- 홈서버의 실제 사설 DB 연결·영속 디스크·별도 장치 백업 위치, 공인 TLS, Google 공개 callback, 최신 이미지 배포와 외부 접근 검증.
- API 세션과 AI 호출 한도는 메모리다. API 재시작 시 재로그인이 필요하며, 여러 replica 전에 공유 세션/한도 저장이 필요하다.
- 실시간 공동 편집과 자동 충돌 병합은 제공하지 않는다. 같은 브라우저의 동시 탭은 이전 탭을 멈추고 초안을 따로 보관한다.
- 초안 파일의 전용 재가져오기 화면은 없다. 충돌 시 내려받기와 별도 로컬 사본을 제공하며 서버 내용으로 바꾸기 전에 보존한다.
