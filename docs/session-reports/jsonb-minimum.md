# JSONB 최소 개선 — 2026-09-28

JSONB 구조와 플랜 단위 저장을 유지하면서 변경 없는 재조회와 저장 영수증의 본문 중복 비용을 줄였다. 커밋·푸시는 하지 않았다.

| 변경 | 적용 내용 | 유지하는 경계 |
|---|---|---|
| 조건부 조회 | 계정·정렬된 버전 메타데이터의 SHA-256 ETag. 일치 시 본문 조회 없이 304 | 인증·기대 계정 검사 우선. 계정 공유 잠금으로 저장과 조회의 세대 일치 |
| 메모리 재사용 | 계정별 API 인스턴스에 검증된 응답과 ETag 보관. 쓰기 시도·조회 오류 시 무효화 | 브라우저 저장소에 전체 사본 추가 없음. 첫 조회·새로고침·변경된 조회는 전체 본문 |
| 저장 영수증 | V3에서 기존/신규 영수증의 본문 제거. 요청 ID·해시·원래 버전/시각 등 메타데이터 유지 | 같은 해시의 재시도 본문으로 원래 응답 복원. 이후 수정/삭제와 무관. 영수증 행은 기한 삭제하지 않음 |
| DB 형식 검사 | 형식 2·레코드 배열·본문 없음 검사. 누락/null도 거부 | 플랜 원본·계정·출처·수정 버전 변경 없음 |

## 검증

| 범위 | 결과 |
|---|---|
| 실제 PostgreSQL API 전체 | 56 통과, 건너뜀 0. 별도 V2 스키마에 기존 영수증을 넣고 Flyway V3 적용·원본 대조·과거 요청 재시도 확인 |
| 저장 로직 | 31 통과. 조건부 조회 6개 포함: 사본 변형 방지·계정 격리·304 검증·응답 유실 시 무효화 |
| 인증·자동 저장 브라우저 | 64 통과 |
| 저장 동기화 브라우저 | 8 통과 |
| 실제 Spring·PostgreSQL·브라우저 | 8 통과. 프록시 경유 200/304·수정 후 200·과거 ACK·계정 격리·재시작·별도 DB dump 복원 |

총 **167개 통과**. 웹 프로덕션 빌드·수정 파일 ESLint·diff 공백 검사 통과. 부하 한계 측정은 아니다. Opus가 API 구현/초기 검증을 담당하고 총괄에서 웹·최종 제약/업그레이드 검증·통합·로컬 반영을 수행했다.

## 로컬 반영

- `http://localhost:3000`의 API·Web에 반영. 프록시·DB 볼륨·Google callback 설정은 유지했다.
- 쓰기를 멈춘 뒤 비공개 DB dump를 생성하고 V3를 적용했다.
- 계정 2개, 저장 레코드 40개, 영수증 4개. 계정·플랜 전체 행 해시와 영수증의 요청 ID/해시/메타데이터 해시가 변환 전후 일치했다.
- 영수증 JSON 합계 `138,463 → 6,257 bytes` (**95.5% 감소**). JSON 논리 크기 기준이며 전체 DB 디스크 감소율이 아니다.
- API 재시작으로 기존 로그인 세션은 만료된다. 재로그인하면 같은 계정의 기존 데이터를 불러온다.
- 실제 3000번 서비스의 새 브라우저에서 랜딩 200·익명 사용자/플래너 조회 401·상태 확인 200, JS 오류/저장 요청/브라우저 저장 0을 확인했다.
- 적용 전 dump와 이전 바이너리는 비공개 임시 작업 폴더에 보존했다. V3 이전 API만 단독으로 되돌리는 것은 호환되지 않는다. [운영 유의점](../postgresql-operations.md) 참고.

## 남은 확장 과제

첫 조회의 전체 로딩, 플랜 전체 단위 쓰기, 작은 영수증 행의 누적은 유지한다. 계정당 데이터 크기와 실제 지연을 측정해 목록/상세 분리 및 영수증 보관 구조를 결정한다. 전체 스냅샷 기반 삭제 판정 때문에 부분 조회만 독립적으로 추가하면 안 된다.
