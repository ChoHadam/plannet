## 발견한 문제와 수정 확인

최종 검토에서 사용법·AI의 코드 로딩 실패 시 화면이 비거나 닫기·복구 수단이 없고, 편집기의 재시도 안내가 실제 동작과 맞지 않는 문제를 발견했다. Opus가 대기/실패 화면, 닫기, 같은 화면에서 재시도, 취소 후 늦게 도착한 코드가 창을 다시 열지 않는 처리를 추가했다.

수정 코드와 최종 로그를 총괄이 검토했다. 수정 전 실패 재현 5개, 수정 후 관련 검사 **9/9 통과**, 타입 검사·변경 파일 lint 통과를 근거로 인수한다. 전체 인증·저장 검사는 변경 범위와 무관하므로 반복하지 않았다. [상세 수정·검증](final-review-followup.md)

## 인수의 한계

- 지연 로딩 재시도 검사는 webpack 빌드다. 운영 Turbopack은 실패한 코드 요청을 캐시하므로 같은 탭 재시도가 다시 실패할 수 있다. 실패 화면은 닫기와 **저장이 끝난 뒤 수동 새로고침**을 안내한다. 페이지를 강제 새로고침하지 않는다. 운영 번들에서 같은 탭 복구 성공까지 보장하는 검증은 아니다.
- 기존 보고의 통과 수는 각 작업 시점·대상에 대한 근거다. 모든 수치를 합쳐 현재 버전의 단일 전체 회귀 결과라고 표현하지 않는다. 이미 통과한 검사는 관련 코드 변경·새 실패·미해결 위험이 있을 때만 다시 실행한다.
- 실제 공개 Google·AI, 공인 TLS, 홈서버 이전·운영 백업, Safari는 이번 인수 범위에 포함하지 않는다. 현재 작업 트리의 검토가 실행 중인 로컬 서비스나 배포 버전의 갱신을 의미하지 않는다.
- W6 저장 형식을 받는 API를 Web보다 먼저 또는 함께 배포해야 한다. 이전 API는 W6 형식을 거부한다.

## W6 검증 인수와 최종 판정

Opus가 추가한 `PlannerMonthlyWeeksPostgresTests`와 격리 실행 driver를 검토했다. 실제 PostgreSQL 18.6에서 W6 저장·계정 격리/잘못된 형식 거부 **2개**, 새 DB 복원 뒤 API 조회·영수증 재전송 **1개**, 기존 PostgreSQL 회귀 **17개**가 통과했다. seed 실행의 복원 사례 1개는 조건부로 건너뛰었고, 실제 복원 뒤 별도 실행에서 통과했다. 통과 수에 skip을 포함하지 않았다.

원본과 새 복원 DB의 사용자 3행·플랜 3행·영수증 7행·migration 이력 3행 지문이 일치했다. API가 복원된 소유자 UUID·본문·버전·ETag를 동일하게 반환했고, 원래 요청 7개 재전송도 원래 ACK를 반환하며 플랜을 다시 쓰지 않았다. DB가 없을 때 필수 검증이 실패하는지와 Gradle이 이전 skip 결과를 재사용하지 않는지도 확인했다. 테스트 입력 선언만 추가한 최종 Gradle 변경에 대해 캐시 검사를 수행했으므로 DB 검사를 반복하지 않았다.

JUnit XML·최종 실행 로그·복원 지문·검토/검증 대상 소스 SHA-256 일치를 확인했다. 검증용 컨테이너·네트워크·볼륨은 제거했고 가상 데이터 증거만 private 임시 디렉터리에 남겼다. 실제 사용자 데이터·서비스는 변경하지 않았다. [W6 실제 DB 상세 보고](w6-postgres-final.md)

**판정: 요청된 최종 코드 검토, 발견 문제의 Opus 수정, W6 격리 저장·복원 검증을 완료했다.** 커밋·푸시·배포·서비스 재시작은 하지 않았다. 위 운영 번들 재시도 제한 및 공개 환경 검증 범위는 그대로 남는다.
