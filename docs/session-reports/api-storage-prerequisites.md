# 이메일 저장 배포의 API 선행 변경

2026-10-05 · 이메일 프로필(V4)을 올리기 전에 검증된 API 저장 변경을 별도 커밋으로 보존한다. Web/UI 변경과 실제 배포·데이터 이전은 이 커밋의 범위가 아니다.

| API 변경 | 동작·호환성 |
|---|---|
| 조건부 스냅샷 | 인증·계정 헤더 확인 후 소유자별 ETag. 계정 행 공유 잠금으로 메타데이터와 본문의 세대를 일치시킨다. 기존 클라이언트의 일반 GET은 계속 200 본문을 받는다 |
| V3 영수증 | 플랜 본문 사본을 제거하고 원래 버전·시각 등 메타데이터 보존. 같은 요청 ID·해시의 재전송으로 원래 ACK 복원. 적용 뒤 V3 이전 API 단독 롤백 금지 |
| 월간 API 호환 | weeklyFocus는 기존 5개(1~5) 또는 6개(1~6)의 중복 없는 주 번호 허용. W6 Web 반영은 별도 |
| 검사 입력 | 실제 PostgreSQL 필수 여부·W6 복원 단계의 환경이 바뀌면 Gradle이 이전 결과를 재사용하지 않게 한다 |

검증 근거: 격리 PostgreSQL에서 W6 저장/계정 격리/형식 검사 2개, 새 DB 복원 후 API 조회·영수증 재생 1개, 기존 PostgreSQL 회귀 17개 통과. seed의 복원 단계 skip 1개는 실제 복원 후 별도 실행에서 통과했다. V3 이전/이후 데이터 보존과 영수증 재시도는 기존 PostgreSQL 테스트에 포함돼 있다. 전체 Web 검사는 반복하지 않았다.

API Controller·Storage의 커밋 내용은 W6 검증 시점 소스 SHA-256과 일치한다. 이메일 단계 최종 API는 관련 검사 49개로 별도 검증했다. 원본 로그·JUnit·SHA-256은 검증용 private 임시 디렉터리에 보존하며 저장소에는 비밀값·실제 사용자 덤프를 넣지 않는다.
