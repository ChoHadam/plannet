# 최종 검토 후속: 지연 로딩 실패 복구

> **10/5 총괄 검토 완료·미배포.** 변경 코드와 최종 통과 근거를 검토했다. 아래 구현 당시 상태는 이 판정으로 갱신한다. 지연 로딩 실패 복구 수정까지 인수했으며, 운영 Turbopack의 같은 탭 재시도는 보장하지 않는다. [최종 코드 검토](final-code-review.md)

2026-10-05 · 작업자 구현·검증 완료, **총괄 검토 대기 · 미배포**. 범위는 Web 지연 로딩 표시만. 저장·인증·API·의존성은 바꾸지 않았다.

## 무엇을 했나

총괄 검토에서 [로딩 최적화](performance.md)의 복구 경로가 없다는 지적(P2)이 나왔다. 이 문제를 고쳤다.

| 지점 | 이전 | 이후 |
|---|---|---|
| 사용법(템플릿 선택·헤더) | 코드 대기·실패 중 아무것도 안 뜸. 템플릿 선택 창도 숨겨져 닫을 방법이 없음 | `사용법` 대화상자에 `불러오는 중...` 또는 실패 안내 + `닫기`·`다시 시도`. 닫으면 템플릿 선택(또는 헤더 버튼)으로 돌아감 |
| AI 어시스턴트 | 한 번 연 뒤 계속 마운트되어 실패하면 새로고침 전까지 빈 상태 | 열려 있을 때만 `AI 어시스턴트` 대기·실패 대화상자를 보여 줌. 닫았다 다시 열어도 실패 안내가 나오며 `다시 시도` 가능 |
| 편집기 | "다른 플랜을 열었다가 다시 열기" 안내. 같은 템플릿의 다른 플랜으로 가도 다시 마운트되지 않음 | 그 자리에서 `다시 시도` 버튼을 누름. 안내는 "계속 실패하면 저장이 끝난 뒤 새로고침" |

```
lazyComponent(load, fallback, failed)
  fallback/failed: ReactNode | (props, retry) => ReactNode
  preload(): 동시 호출은 한 Promise 공유 · 실패 시 캐시 비움 · 성공한 코드는 유지
  retry(): 오류 상태 해제 → 같은 인스턴스에서 다시 받기 (페이지 새로고침 없음)
  언마운트(닫기) → live=false → 늦게 온 코드가 닫힌 창을 열지 않음
```

- `LazyLoadDialog`는 기존 `useModalDialog`를 쓴다. 초점 진입, Tab 순환, Esc·배경 클릭 닫기, 연 버튼으로 초점 복귀를 지원하고, 버튼에는 `FOCUS_RING`을 적용했다. `다시 시도`를 누르면 버튼이 사라지므로 초점을 `닫기`로 옮긴다.
- 코드가 도착하면 이 자리 표시 대화상자가 실제 사용법으로 바뀐다. 이때 초점은 실제 사용법이 다시 가져간다.

## Turbopack 주의 (확인한 사실)

- 운영 Dockerfile은 `next build`(Next 16 기본값 Turbopack)로 빌드한다. 테스트 스위트는 `next build --webpack`으로 빌드한다.
- 설치된 Next 16.3.8 Turbopack 브라우저 런타임(`chunkResolvers`, `loadingStarted`)을 보면 실패한 코드 묶음의 거부 Promise를 URL별로 계속 보관한다. 그래서 **운영 빌드에서는 같은 탭에서 다시 시도해도 같은 코드 묶음이 다시 실패할 수 있다**. webpack은 실패한 묶음을 지우고 다시 요청하며, 테스트로 복구를 확인했다.
- 따라서 운영에서 보장하는 것은 다음과 같다. 언제나 닫고 작업으로 돌아갈 수 있다. 실패 안내는 "저장이 끝난 뒤 새로고침"을 함께 알린다. 미저장 수정은 기존 sessionStorage 임시 보관과 이탈 경고가 보호한다. Turbopack 빌드는 이번 단계에서 실행하지 않았다(아래 미검증).

## 검증

| 검사 | 결과 |
|---|---|
| `tsc --noEmit`(e2e 포함), 변경 파일 eslint | 통과 |
| 수정 전 소스 재현: 새 UI 실패·취소 테스트 5개 | **5개 모두 실패**(대화상자·다시 시도 없음) |
| 최종 소스: `ux-foundation` 중 새 6개 + 기존 지연 로딩 2개(헤더 사용법 초점·이모지 저장, 로그아웃 ACK 대기) + 템플릿→사용법→날짜 키보드 1개 | **9/9 통과** |

새 테스트는 `e2e/ux-foundation/ux-foundation.spec.ts`의 `지연 로딩 실패·취소`에 있다. 코드 묶음 요청은 브라우저에서 실패시키거나 붙잡았고, 인증·DB·AI는 가상 응답을 썼다.
- helper: 동시 요청을 1회로 합치는지, 실패 뒤 다시 받는지, 성공한 코드를 유지하는지 확인했다(브라우저 없음).
- 사용법 실패: Esc로 템플릿 선택에 돌아가고, 다시 열어도 실패 안내가 나오며, 다시 시도하면 사용법이 열리는지 확인했다. 페이지는 새로고침되지 않았다.
- 사용법·AI 로딩 중 닫기: 연 버튼으로 초점이 돌아오는지 확인했다. 코드 묶음을 늦게 보낸 뒤에도 창이 열리지 않았다.
- AI 실패: 저장 대기 중인 제목 수정을 유지한 채 닫기 → 다시 열기 → 다시 시도로 복구되는지 확인했다. 그 뒤 DB 반영도 확인했다. 실제 AI 요청은 0회였다.
- 편집기 실패: 같은 플랜에서 다시 시도하면 Block6 편집기가 열리는지 확인했다.

첫 실행에서 테스트 1개가 실패했다. 테스트 코드 문제였다: `'사용법'` 이름 부분 일치가 `투두리스트 사용법`도 잡았다. `exact: true`로 고치고 다시 실행했다. 앱 코드는 바뀌지 않았다.

전체 인증·저장·템플릿 묶음은 실행하지 않았다. store, 동기화, 인증 코드를 건드리지 않았기 때문이다. 이전 최종 UX27·storage68 통과를 기준선으로 쓴다.

## 미검증·후속

- Turbopack 운영 빌드의 실제 실패·재시도 동작은 브라우저로 확인하지 않았다. 런타임 소스로 재시도가 다시 실패할 수 있다고 판단했을 뿐이다. 운영에서 같은 탭 재시도가 필요하면 빌드 방식이나 새로고침 안내를 결정해야 한다(총괄 판단).
- 이모지 선택 창("닫았다가 다시 열기" = 다시 마운트, 정상)과 작업 공간 전체 실패 화면(편집 전이라 새로고침이 안전함)은 바꾸지 않았다.
- 이 단계의 성능 수치는 webpack 기준이다([성능 보고](performance.md)).
