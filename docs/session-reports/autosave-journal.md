# 자동 저장 임시 보관 (sessionStorage)

2026-09-28 · 기준 `3e08caa` + 미커밋 변경. 사용자 요청: "변경 사항이 있을 때마다 자동 저장 … 임시성으로는 브라우저 저장이어도 돼. 가장 가벼운 방법으로." 이전 [DB 전용 저장](./db-only-storage.md)(대체됨)에 **미확인 변경분 임시 보관**만 더했다.

## 설계

| 항목 | 내용 |
|---|---|
| 위치 | sessionStorage 키 하나 `plannet-pending@<검증된 내부 UUID>`. 탭마다 따로, 새로고침에는 남고 탭을 닫으면 사라진다 |
| 내용 | `{ format: 1, userId, savedAt, drafts, inflight }`. 바뀐 기록(원래 기대 버전 포함)과 정확한 전송 중 요청뿐. 서버 기록 전체·기준 사본 없음 |
| 쓰기 | 수정 직후(650ms DB 디바운스 전), 전송 요청을 만든 뒤 **POST 전**, 각 응답 처리 뒤, 명시적 버리기 뒤. 깨끗해지면 이 키만 지운다 |
| 복원 | 같은 계정으로 로그인하고 DB 조회가 성공한 뒤에만. DB와 같은 변경분은 정리하되, 전송 중인 기록의 후속 수정·실행 취소는 보존한다. 모든 초안과 전송 중 요청의 문서를 검증한 뒤 적용한다(새 초안에 가려진 이전 요청도 검증). 전송 중 요청은 같은 requestId로 먼저 재전송(영수증으로 중복 없음). 더 새로운 DB 버전이면 409 충돌(자동 재기준 없음) |
| 실패 | 쓰기 실패(차단·용량·속성 접근 거부)는 DB 저장을 막지 않고 "새로고침 대비 임시 보관을 쓸 수 없어요" 안내만. 다음 변경 때 다시 시도 |
| 깨진 보관 | 형식·계정·requestId·문서 검증 실패 시 적용·덮어쓰기·삭제하지 않는다. 파일 저장과 확인 후 삭제만 제공하고, 삭제 전까지 새 임시 보관 쓰기를 멈춘다(DB 저장은 계속) |
| 로그아웃·이탈 | 미저장 시 `beforeunload` 확인과 로그아웃 전 저장은 그대로. 첫 DB 조회가 실패해도 복원 대기 중인 보관이 있으면 미저장으로 보아 로그아웃을 막는다. 보관이 없으면 로그아웃할 수 있다 |

다른 계정 키·로그인 전 화면은 이 보관을 읽지 않는다. 명시적 `AUTH_ENABLED=false` 로컬 모드, 예전 LocalStorage 원본(읽기 전용 가져오기·파일 저장)은 바뀌지 않았다. 탭 닫기·브라우저 종료 뒤 복구는 약속하지 않는다.

| 대상 | 결과 |
|---|---|
| `tsc --noEmit`, `eslint src e2e` | 통과 |

개발 중 단위 테스트 실패 2건: 고정 요청 ID(`request-N`)를 총괄이 강화한 UUID 검사가 거부했고(픽스처를 UUID로 수정), 공유 픽스처의 이전 적용 결과를 잘못 단언했다(엔진별 적용 기록으로 수정). mandalart-io 등 로컬 모드 전용 suite와 kind 클러스터 검증은 이번에 실행하지 않았다. 이전 201개 실행 수치는 과거 기록이며 이번 수치에 합산하지 않는다.

## 한계

- 탭 복제(Chrome "탭 복제")는 sessionStorage를 복사한다. 두 탭이 같은 변경분을 보내면 하나는 영수증 또는 409 충돌로 끝난다(중복 반영은 없다).
- 강제 종료·탭 닫기 사이의 미확인 변경은 복구되지 않는다.
- 선택한 플랜·조회 기간은 새로고침 뒤 초기화된다.

## 총괄 검토·로컬 반영

- 복원 요청 ID를 API 계약과 같은 UUID로 제한하고, 새 초안에 가려진 이전 전송 내용까지 검증하도록 보강했다. `load-validation.spec.ts` 6개는 위 storage-sync 33개에 포함된다. 손상된 이전 요청 차단과 전송 중 실행 취소 후 새로고침 복구도 검증했다.
- 이번 공식 회귀는 **172개**(74 + 33 + 7 + 34 + 15 + 9) 통과했다. 최종 빌드 `UYvbaK39qtujApLqC0y06`과 소스 입력 107개를 대조해 로컬 `http://localhost:3000`에 반영했다. 기존 API·DB·진입 프록시는 유지했다.
- 배포할 동일 빌드의 별도 브라우저 검사 2개도 통과했다. 저장 대기에는 변경한 기록만 있는 임시 키 1개, DB 확인 후 0개, LocalStorage 쓰기 0회였다. sessionStorage 접근 자체를 차단한 경우에도 DB 저장·재진입 조회가 성공했다. 원본 및 무관한 임시 설정은 보존됐고 브라우저 오류는 없었다.
- 실제 브라우저에서 로그인 랜딩·로그인 버튼 1개·작업 공간 비노출을 확인했다. 배포 전후 LocalStorage의 원본 16개 키와 각 값의 SHA-256이 모두 일치하고, 익명 상태의 임시 변경분은 0개였다. 원문 반환 검사는 한 차례 시간 초과되어 내용 대신 해시를 대조했다. 실제 사용자 플랜을 수정하거나 다시 이전하지 않았다.
- 저장/복구 검증용 별도 서버는 종료했다. 3000번 로컬 서비스는 유지한다. 로드맵·저장 설계·운영 지침을 갱신했으며 커밋·push는 하지 않았다.
